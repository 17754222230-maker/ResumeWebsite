## 一、ERP 财务模块到底管什么？

ERP 的财务模块不是单纯“记账”，它本质上是企业经营结果的最终归集层。

业务上可以理解为：

采购、销售、库存、生产、质检、合同、发票、付款、收款，最后都会落到财务模块，形成应收、应付、凭证、成本、利润和资金流水。

常见财务模块包括：

- 总账 GL：企业所有会计凭证最终汇总的地方。
- 应收 AR：客户欠公司多少钱，公司该收多少钱。
- 应付 AP：公司欠供应商多少钱，公司该付多少钱。
- 固定资产 FA：设备、厂房、车辆等资产管理。
- 成本核算 CO：生产成本、材料成本、人工、制造费用归集。
- 资金管理：银行账户、付款计划、收款流水、票据。
- 税务/发票：进项发票、销项发票、开票、抵扣。
- 预算管理：费用预算、项目预算、部门预算控制。

你面富冶这个岗位，最该重点准备的是：

应收、应付、结算、发票、客户供应商主数据、采购销售财务联动。

## 二、客商系统是什么？你可以这样理解

你说的“客商系统”，在 ERP 里一般属于主数据管理的一部分。

“客商”通常指：

- 客户：买我们东西的人/公司。
- 供应商：卖东西给我们的人/公司。
- 既是客户又是供应商的单位：比如集团内公司、贸易伙伴，既买又卖。
- 承运商、服务商、代理商：也可能纳入客商体系。

### 客商系统一般管哪些信息？

#### 1. 基础档案

- 客商名称
- 统一社会信用代码
- 企业类型
- 注册地址
- 法人
- 联系人
- 联系电话
- 邮箱
- 纳税人识别号

#### 2. 财务信息

- 开户银行
- 银行账号
- 开票信息
- 税率
- 结算币种
- 结算方式
- 付款条件
- 信用额度

#### 3. 业务属性

- 是客户还是供应商
- 所属行业
- 客户等级
- 供应商等级
- 是否集团内单位
- 是否黑名单
- 是否启用
- 所属业务部门
- 所属销售员/采购员

#### 4. 风控信息

- 资质证照
- 营业执照有效期
- 合同有效期
- 信用等级
- 是否冻结交易
- 是否允许赊销
- 是否允许预付款

## 三、客商系统为什么重要？

你面试时可以这样说：

客商主数据是 ERP 里非常核心的基础数据。采购、销售、合同、开票、收付款、应收应付、对账都依赖客商数据。如果客商数据不准确，后面的业务单据、财务结算、税务开票都会出问题。

比如：

- 客户开票信息错了，会导致发票开错；
- 供应商银行账号错了，会导致付款风险；
- 客户信用额度没控制，会导致坏账风险；
- 客商重复建档，会导致应收应付对账混乱；
- 客商状态没有冻结，会导致黑名单客户继续交易；
- 税号、公司名称不一致，会影响税务合规。

所以客商模块不是简单 CRUD，它其实承载了企业主数据治理、财务风控和业务合规。

这句话很适合面试：

我理解客商系统不是单纯维护企业资料，而是贯穿采购、销售、合同、财务、开票、收付款的一套主数据底座。

## 四、应收 AR 是什么？

应收账款，英文一般叫 AR：Accounts Receivable。

简单说：

公司把货卖给客户了，客户还没付款，这笔客户欠公司的钱，就是应收。

### 应收的典型业务链路

以制造业销售为例：

```plain
销售合同/销售订单
        ↓
发货/出库
        ↓
确认收入
        ↓
生成应收单
        ↓
开具销项发票
        ↓
客户付款
        ↓
收款核销
        ↓
应收关闭
```

### 应收系统常见单据

- 销售订单
- 出库单
- 应收结算单
- 销项发票
- 收款单
- 核销单
- 红冲单/退款单
- 对账单

## 五、应收结算单是什么？

你之前说你做过应收应付结算单，这个要重点准备。

### 应收结算单可以理解为：

系统根据销售业务、发货记录、合同价格、税率、客户信息等，计算出客户应该付多少钱，形成一张财务结算依据。

它不是最终收款，而是告诉财务：

这批货/这笔业务已经满足结算条件，客户应该向我们付款多少。

### 应收结算单常见字段

- 结算单号
- 客户 ID / 客户名称
- 合同号
- 销售订单号
- 出库单号
- 物料/商品信息
- 数量
- 单价
- 含税金额
- 不含税金额
- 税额
- 税率
- 币种
- 结算状态
- 开票状态
- 收款状态
- 业务日期
- 财务日期
- 创建人/审核人

### 应收结算单状态

常见状态可以这样理解：

```plain
草稿 → 已提交 → 已审核 → 已开票 → 部分收款 → 已收款/已核销 → 关闭
```

也可能有：

- 已驳回
- 已作废
- 已红冲
- 部分核销
- 已冲销

## 六、应付 AP 是什么？

应付账款，英文一般叫 AP：Accounts Payable。

简单说：

公司向供应商买了货或服务，还没付款，这笔公司欠供应商的钱，就是应付。

### 应付的典型业务链路

```plain

        ↓

        ↓

        ↓
质检验收
        ↓
供应商开票
        ↓
生成应付结算单
        ↓
付款申请
        ↓
付款审批
        ↓
银行付款
        ↓
付款核销
        ↓
应付关闭
```

### 应付系统常见单据

- 采购订单
- 入库单
- 质检单
- 应付结算单
- 进项发票
- 付款申请单
- 付款单
- 核销单
- 预付款单
- 对账单

## 七、应付结算单是什么？

### 应付结算单可以理解为：

系统根据采购入库、质检结果、合同价格、发票信息等，计算出公司应该付给供应商多少钱。

制造业里面应付很复杂，因为它可能涉及：

- 原料采购；
- 检斤；
- 化验；
- 品位；
- 扣杂；
- 质量扣款；
- 运费；
- 预付款；
- 票据；
- 税率；
- 多币种；
- 合同定价公式。

尤其富冶是有色金属行业，原材料可能涉及矿粉、铜精矿、金属含量、计价周期、品位、杂质扣减等，财务结算比普通电商更复杂。

你可以在面试中说：

制造业应付结算不只是按采购数量乘单价，还可能和质检结果、入库数量、合同条款、扣款规则、税率、发票、预付款抵扣等有关。

这句话很专业。

## 八、应收和应付的核心区别

你可以这样记：

| 类型    | 谁欠谁钱       | 来源业务 | 关键对象 |
| ------- | -------------- | -------- | -------- |
| 应收 AR | 客户欠公司钱   | 销售业务 | 客户     |
| 应付 AP | 公司欠供应商钱 | 采购业务 | 供应商   |

一句话：

应收看客户，关注收钱；应付看供应商，关注付款。

## 九、结算、开票、收付款、核销是什么关系？

这个非常重要，面试很可能问。

### 1. 结算

结算是算账：

根据业务单据计算该收多少钱或该付多少钱。

例如：

- 卖了 100 吨铜，单价 8 万，总金额 800 万；
- 采购了 50 吨矿粉，按照品位和扣杂规则结算，应该付 300 万。

### 2. 开票

开票是税务凭证：

- 应收侧：我们给客户开销项发票。
- 应付侧：供应商给我们开进项发票。

结算金额和发票金额通常要匹配，但也可能存在部分开票、暂估、红冲。

### 3. 收付款

- 应收：客户把钱打给我们，形成收款单。
- 应付：我们把钱打给供应商，形成付款单。

### 4. 核销

核销是把“账”和“钱”对上：

- 应收核销：某笔收款对应冲掉哪几张应收单。
- 应付核销：某笔付款对应冲掉哪几张应付单。

举例：

```plain
客户 A 有三张应收单：
应收单1：10万
应收单2：20万
应收单3：30万

客户打款 25万。

财务可以核销：
应收单1 10万全部核销
应收单2 15万部分核销
剩余应收：应收单2 5万 + 应收单3 30万
```

这就是核销。

## 十、制造业 ERP 财务和普通互联网系统有什么不同？

你可以重点说这几个点。

### 1. 单据链路长

互联网系统可能一笔订单直接支付完成。

制造业 ERP 是：

```plain
合同 → 订单 → 发货/收货 → 质检 → 入库/出库 → 结算 → 开票 → 收付款 → 核销 → 凭证
```

每一步都有状态，每一步都可能影响财务。

------

### 2. 结算规则复杂

尤其有色金属行业：

- 数量可能来自过磅；
- 质量可能来自化验；
- 价格可能来自合同公式；
- 税率可能不同；
- 运费、杂费、扣款、补差都可能参与结算；
- 可能存在暂估入账、后续调整。

------

### 3. 财务强一致性要求高

财务系统不像普通业务系统，不能随便改。

要关注：

- 金额精度；
- 审批流程；
- 操作留痕；
- 数据不可随意删除；
- 红冲/反审核机制；
- 权限控制；
- 对账一致性；
- 幂等和重复提交；
- 事务一致性。

你可以这样说：

财务模块开发我会特别关注金额精度、单据状态流转、审批留痕、幂等、防重复提交，以及业务单据和财务单据之间的数据一致性。

这句话很加分。

## 十一、ERP 财务模块开发常见技术点

虽然它是业务模块，但技术上也有套路。

### 1. 金额字段

通常用：

- Java：`BigDecimal`
- 数据库：`DECIMAL`
- 禁止用 `double` / `float`

原因：

金额计算要求精确，浮点数会有精度误差。

------

### 2. 单据号生成

结算单、收款单、付款单通常都有单据号：

```plain
AR202605190001
AP202605190001
SETTLE202605190001
```

要考虑：

- 唯一性；
- 按日期/组织/业务类型编码；
- 并发生成；
- 可读性。

------

### 3. 状态机

财务单据通常有明确状态：

```plain
草稿 → 提交 → 审核 → 已开票 → 已核销 → 关闭
```

开发时要防止非法状态流转，比如：

- 已审核单据不能随便修改；
- 已核销单据不能删除；
- 已付款单据不能重复付款；
- 已开票单据作废要走红冲流程。

------

### 4. 审批流

财务相关系统通常接 OA 或内部流程引擎：

- 付款申请审批；
- 供应商新增审批；
- 客户信用额度审批；
- 结算单审核；
- 发票红冲审批。

------

### 5. 对账

对账是 ERP 财务里的高频场景：

- 客户对账；
- 供应商对账；
- 银企对账；
- 发票对账；
- 库存与财务对账；
- 业务单据与财务单据对账。

------

### 6. 接口集成

财务模块经常和外部系统交互：

- 税控/开票系统；
- 银企直连；
- OA审批；
- 主数据平台；
- 采购系统；
- 销售系统；
- 仓储系统；
- MES；
- 总账系统。

你做过“各种基础数据接口”，这很好讲。

## 十二、你面试时可以怎么包装你做过的财务和客商模块？

你可以这样说：

我之前参与过 ERP 系统里的客商和财务相关模块。客商模块主要负责客户、供应商等企业主数据维护，包括企业基础信息、财务开票信息、银行账户、业务属性、启停状态，以及对外部系统的数据接口同步。这个模块虽然看起来是基础资料维护，但实际上会影响采购、销售、合同、开票、应收应付和结算，所以对数据准确性、唯一性和接口一致性要求比较高。

然后接财务：

财务模块我参与较多的是应收、应付结算单相关开发。我的理解是，应收主要来源于销售业务，关注客户应该向公司支付的款项；应付主要来源于采购业务，关注公司应该向供应商支付的款项。结算单是业务单据到财务单据之间的关键桥梁，它会根据订单、出入库、合同价格、税率、发票、付款条件等信息生成结算依据。开发时我比较关注金额精度、状态流转、审批留痕、防重复提交、与上下游单据的数据一致性。

这段你可以直接背。

## 十三、如果面试官追问：“你做的应收应付结算单具体有什么难点？”

你可以回答：

我理解结算单开发的难点主要不在页面 CRUD，而在业务规则和数据一致性。比如一张结算单可能来源于多张业务单据，需要处理数量、金额、税额、折扣、扣款、发票、已收已付金额等字段；同时还要控制状态流转，比如已审核、已开票、已核销之后不能随意修改。

技术上我会关注 BigDecimal 金额精度、数据库事务、接口幂等、重复提交控制、单据状态校验，以及异常情况下的回滚和日志追踪。

如果想更贴制造业一点，可以加：

制造业场景下，结算金额还可能和入库数量、质检结果、合同价格、扣款规则有关，所以业务规则会比普通订单系统更复杂。

## 十四、如果面试官问：“客商系统怎么避免重复建档？”

可以这么答：

一般会通过统一社会信用代码、纳税人识别号、企业名称、银行账号等关键字段做唯一性校验。实际系统里企业名称可能存在简称、全称、历史名称，所以不能只靠名称判断，统一社会信用代码是更可靠的唯一标识。

同时，对于既是客户又是供应商的企业，可以设计成同一个客商主体下挂不同角色，而不是重复创建两份档案。这样后续应收应付、对账、往来余额查询会更清晰。

这个回答很专业。

------

## 十五、如果面试官问：“应收应付怎么和总账关联？”

可以这么答：

应收应付属于业务财务模块，总账是最终会计核算模块。应收、应付单据审核后，通常会按照会计科目、业务类型、部门、客商、税率等信息生成会计凭证，然后传递到总账。

比如销售确认应收时，会形成类似“借：应收账款，贷：主营业务收入/销项税额”的凭证；采购形成应付时，会形成类似“借：原材料/库存商品/进项税额，贷：应付账款”的凭证。开发上主要是保证业务单据和凭证之间有关联关系，并且凭证生成、冲销、红冲都有可追溯链路。

你不用说得像会计一样精确，但这个方向要懂。

------

## 十六、如果面试官问：“应收和收款有什么区别？”

你可以这样说：

应收是债权，是客户应该付给公司的钱；收款是资金实际到账。

有应收不代表已经收到钱，有收款也不一定完全对应某一张应收单，所以需要通过核销把收款和应收单据关联起来。核销后，应收余额才会减少。

------

## 十七、如果面试官问：“应付和付款有什么区别？”

你可以这样说：

应付是公司对供应商的债务，表示公司应该付多少钱；付款是资金实际支付动作。

应付单据审核后不一定马上付款，可能要走付款计划、付款申请、审批、资金排程。付款完成后再做核销，减少对应供应商的应付余额。

我之前做过 ERP 系统中的客商和财务相关模块。客商模块主要负责客户、供应商等企业主数据维护，包括基础信息、开票信息、银行账户、业务属性、启停状态，以及和其他系统的数据接口同步。我理解客商数据是 ERP 的基础底座，会影响采购、销售、合同、开票、应收应付、对账等多个环节，所以开发时比较关注数据唯一性、准确性、接口一致性和状态控制。

财务模块方面，我主要参与过应收、应付结算单开发。我的理解是，应收是销售业务形成的客户欠款，应付是采购业务形成的供应商债务，结算单是业务单据进入财务核算的重要桥梁。开发时不仅要处理金额、税额、发票、收付款、核销等业务字段，还要关注 BigDecimal 金额精度、单据状态流转、审批留痕、防重复提交、事务一致性，以及和上下游系统的数据对账。

如果结合制造业场景，我认为 ERP 财务的复杂度主要来自采购、销售、库存、质检、合同和财务之间的协同，特别是有色金属行业还会涉及重量、品位、扣款、价格公式等结算规则。我对这类制造业信息化业务比较感兴趣，也希望后续能结合企业内部知识库和 Agent 能力，提升 ERP 操作、对账、报表和问题排查效率。
