## 一、命局简析与色彩格局

**命盘**  
乾造：庚辰 癸未 己丑 戊辰  
日主己土，生于未月，四柱地支辰、未、丑、辰全土，天干戊土劫财帮身，土势极重。  
庚金伤官透年，癸水正财透月，全局土旺、身强，**取金泄土、水制火调候，喜金水，忌火土。**

**配色方案（直接从命理映射到UI）**  
- **主色**：深蓝（水色，代表财富、流动） `#0B1D3A`、`#102A43`  
- **辅色**：金色/浅金（金色泄秀，代表才华）`#D4AF37`、`#C5A860`  
- **背景**：微冷白或极浅灰蓝，杜绝土黄、棕、红色系  
- **点缀**：银白、墨绿（木受水生，可为点睛），可用在标题或logo  
- **质感**：可引入微水波纹、金属光泽或磨砂玻璃效果，忌厚重土块质感

**风格关键词**：现代科技感 + 一点东方雅致，留白充足、呼吸感强。

## 二、优化后的项目提示词（可直接交付开发）

以下是一份结构化需求说明，面向全栈工程师或 AI Coding Agent：

---

```markdown
# 个人简历 & 智能知识站 项目需求书

## 1. 总体目标
构建一个展示个人技术能力、项目经历，并内置 AI 知识助手的个人网站。
站点需体现简约、现代、略带东方韵味的视觉风格，色彩遵从命理喜用（金水）。

## 2. 功能需求

### 2.1 主页面（个人简介）
- 英雄区：个人姓名、Title、一句话 Slogan。
- 技术栈展示区：以图标/标签云展示核心技能（语言、框架、工具等）。
- 个人优势区：用简短条目突出技术亮点、软技能、行业认知。

### 2.2 项目卡片矩阵
- 位于主页下方，以卡片网格展示所有项目（缩略图、名称、简介、主要技术标签）。
- 每个卡片可点击，进入独立项目详情页。
- 项目详情页需包含：
  - 项目背景 / 目标
  - 个人职责与主要工作内容
  - 技术栈详细列举
  - 关键成果 / 链接

### 2.3 AI 智能助理（侧边悬浮组件）
- 位于主页面右下或右侧边栏，展示个人虚拟形象。
- 核心功能：通过对话式界面回答访客关于“我”的问题，例如：
  - “你擅长哪些技术栈？”
  - “你做过哪些项目？”
  - “你在 XX 项目中负责什么？”
  - “你的工作经历是？”
- 知识来源：采用 **Wiki 式知识卡片** 存储，每张卡片包含标题、正文、标签。
- Agent 可调用简单 MCP 工具：查询技能列表、查询项目详情、查询个人信息等。
- 回复风格：专业、友好、简洁。

### 2.4 内容管理
- 项目与知识卡片以结构化文件存储（Markdown / YAML / JSON），便于随时增改。
- 知识卡片分为多类：`技能` `项目` `经历` `其他`。

## 3. 八字色彩设计约束
- 主色系：深蓝、藏青、金色（金/白）。
- 禁用大面积红、橙、黄、土棕。
- 背景宜冷色调，文字用白色/浅灰。
- 建议加入少许水波纹或金属肌理装饰。

## 4. 非功能性需求
- 响应式设计，适配移动端。
- 首屏加载迅速，SSG 优先。
- 易于部署和后续扩展（例如增加博客、后台）。

## 5. 后续迭代方向
- 项目可过滤/搜索
- AI 助手支持多轮深度对话
- 集成更多外部数据源（如实时 GitHub 贡献）
```

## 三、初始技术选型与架构建议（讨论版）

### 1. 前端
| 项目     | 推荐                                         | 理由                                                         |
| -------- | -------------------------------------------- | ------------------------------------------------------------ |
| 框架     | **Next.js 14** (App Router) + **TypeScript** | 静态生成项目详情页极快，利于 SEO，同时可内建 API Route 对接 Agent |
| UI 库    | **Tailwind CSS** + **shadcn/ui**             | 组件可高度自定义，配色可完美映射八字的蓝金系统               |
| 动画     | **Framer Motion**                            | 卡片出入场、AI 形象微动效都自然                              |
| 项目内容 | **MDX** 文件                                 | 支持 Markdown + 自定义 React 组件，内容与样式解耦            |

### 2. AI Agent 与后端
| 模块         | 方案 A（Node 全栈）                             | 方案 B（Python 微服务）                     |
| ------------ | ----------------------------------------------- | ------------------------------------------- |
| 框架         | Next.js API Route + Vercel AI SDK               | FastAPI + LangChain / LlamaIndex            |
| LLM          | OpenAI GPT-4o-mini （通过 AI SDK）              | OpenAI / 国产模型（DeepSeek、智谱）         |
| 知识检索     | 向量搜索：Pinecone / Qdrant / pgvector          | 向量搜索：Chroma / Qdrant                   |
| MCP 工具     | 直接用 AI SDK 的 `tool()` 定义函数              | 利用 LangChain Tool 抽象，可接入 MCP Server |
| 知识卡片存储 | 构建时解析 Markdown → 生成 JSON，运行时分段嵌入 | 同上，或通过 FastAPI 实时加载并向量化       |

> **初期推荐**：如果团队偏 JS，走 **方案 A**，Vercel AI SDK 构建 Agent 非常简洁，可轻松实现 MCP 式工具调用。  
> 如果未来要跑复杂的 Agent 链路或本地模型，后期再拆出 **方案 B** 作为独立服务。

**知识问答流程**  
1. 知识卡片（.md/.yaml）在构建/启动时转为文本块  
2. 用 Embedding 模型（如 text-embedding-3-small）转为向量，存入向量库  
3. 用户提问 → Agent 调用“搜索知识库”工具 → 取出相关卡片内容 → 生成回答  
4. 一些固定问题（如“技术栈列表”）可直接用 function calling 返回结构化数据，避免幻觉

### 3. 部署与云服务
| 部署对象   | 推荐方案                                                 | 备选                     |
| ---------- | -------------------------------------------------------- | ------------------------ |
| 静态前端   | **Vercel**（免费，国内访问可加域名） 或 阿里云 OSS + CDN | Cloudflare Pages         |
| Agent API  | **阿里云 ECS**（1c2g 即可） + Docker                     | 阿里云函数计算 FC + 日志 |
| 向量数据库 | Qdrant 自托管 或 阿里云 Elasticsearch                    | Supabase pgvector        |

**推荐初期部署方案**（兼顾国内访问与成本）：
- 前端 Next.js 静态导出 → 部署到 **阿里云 OSS**，用 CDN 加速，域名绑定。
- AI Agent 打包为 Docker，部署在 **阿里云 ECS** 上，占用 3000 端口，Nginx 反向代理 + HTTPS。
- 知识卡片一并打入 Docker 或通过 Volume 挂载。
- 向量数据库可直接用 **Qdrant 单节点容器** 部署在同一 ECS 上，初期待检索数据量小时毫无压力。

### 4. MCP 的“简单落地”
采用 **MCP 思想**，不必部署完整 MCP Server，只需在 Agent 端提供几个工具：
- `get_skill_list()`
- `search_projects(query: str)`
- `get_personal_info(field: str)`

这些函数读取知识卡片或缓存数据，Agent 自动判定何时调用，访客根本感受不到工具存在，只觉得你有个智能分身在答问。
