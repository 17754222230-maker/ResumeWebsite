### 二、 核心优化建议（架构师视角）

您文档中的技术选型（Next.js + Tailwind + Vercel AI SDK/FastAPI + Qdrant）已经非常优秀，但我为您做以下**落地优化**：

#### 1. 前端工程优化（金之锐利）

- **优化点**：文档提到用MDX，但对于纯展示型简历和知识卡片，建议**降级为纯 Markdown + `gray-matter` (Frontmatter解析)**。
- **理由**：MDX虽然强大，但会增加构建复杂度和包体积。简历站点的核心是“快”和“SEO”。纯Markdown配合Next.js的 `generateStaticParams` 可以实现100%的静态预渲染（SSG），达到极致的首屏速度（风水上的“气速达”）。
- **UI组件**：`shadcn/ui` 是绝佳选择，但请务必在 `tailwind.config.js` 中严格锁死您的“八字喜用色”（深蓝 `#0B1D3A`、金色 `#D4AF37`），禁用默认的主题色，防止开发时误用“火土”色系（红/黄/棕）。

#### 2. AI Agent 与后端优化（水之灵动）

- **优化点**：初期**不要**引入沉重的向量数据库（如Qdrant/Pinecone）。
- **理由**：个人简历和知识卡片的数据量通常在几十到几百篇之间，文本分块后不过几百个向量。使用重型向量库是“杀鸡用牛刀”，增加运维成本（土重埋金）。
- **替代方案**：使用 **内存向量检索**（如 Vercel AI SDK 自带的简单相似度计算，或 `hnswlib-node` / `Faiss` 的轻量级封装），甚至在数据量极小时，直接通过 **LLM 的 Context Window (上下文窗口) + Function Calling** 将结构化JSON喂给大模型。等知识卡片超过500篇，再迁移至 `pgvector` (Supabase) 或 `Qdrant`。

#### 3. 部署架构优化（因地制宜）

- **国内访问痛点**：Vercel 在国内访问存在被墙或减速的风险（风水上的“路冲”）。

- 优化方案

  ：

  - **前端**：Next.js 使用 `output: 'export'` 导出纯静态HTML/CSS/JS，部署到 **阿里云OSS + CDN** 或 **Cloudflare Pages**（若面向海外/技术圈）。
  - **后端(AI Agent)**：由于需要调用大模型API，国内服务器调用海外API需代理，国内大模型（如DeepSeek、Kimi、智谱）则无需。建议将Agent部署在 **阿里云函数计算 (FC)** 或 **轻量应用服务器** 上，按量付费，成本极低。
